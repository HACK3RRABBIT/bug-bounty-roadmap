# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A day-by-day, 100% free bug bounty learning roadmap (Persian + English), published as three
independent front-ends plus a local functional prototype — all driven from one canonical dataset.

## Commands

```bash
# Regenerate canonical content (never hand-edit the JSON files — edit these scripts instead)
python3 generate_roadmap.py       # -> data/roadmap.json     (Persian, source of truth)
python3 generate_roadmap_en.py    # -> data/roadmap.en.json  (English, structural mirror of FA)
python3 scripts/build_en_page.py  # -> en/index.html         (regenerates from index.html)

# Preview the static sites (root, /en/) locally
python3 -m http.server 8000

# Flask app (app/) — auth, roles, admin panel, SQLite
cd app && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python server.py        # http://localhost:9876
# managed on this machine as the systemd user service `bug-bounty-roadmap-app.service`

# Next.js app (web/) — the animated "v2" design
cd web && npm install
npm run build                     # root-basePath build -> web/out (matches local systemd service)
NEXT_PUBLIC_BASE_PATH=/bug-bounty-roadmap/v2 npm run build   # subpath build for GitHub Pages /v2/
npm run lint
# root-basePath build is served on this machine as `bug-bounty-roadmap.service` (port 3000)

# telegram/ — Telegram learning-companion sync (read-only scan+match+preview only; see telegram/README.md)
python3 -m telegram.sync scan --fixture telegram/fixtures/sample_source_messages.json
python3 -m telegram.sync preview --days 1,10,19,46
python3 -m unittest discover -s telegram/tests -t . -v
```

The only test suite in this repo is `telegram/tests/` (plain `unittest`, no pytest). Everything
else has no tests.

## Architecture: one dataset, three independent front-ends

The roadmap's day/phase content lives in exactly one place — `data/roadmap.json` (Persian) and
`data/roadmap.en.json` (English) — produced by `generate_roadmap.py` / `generate_roadmap_en.py`.
Both generators build a list of `phase()` blocks containing `d()` (day) calls, then run every
phase through `compact()`, which merges consecutive days down to a per-phase target in
`COMPACTION_TARGETS` so a "day" reflects real study time (hours are **not** capped — a day can be
2–8h depending on how much content got merged into it). **The FA and EN generators must keep the
same `COMPACTION_TARGETS` and phase order**, because day numbers are meant to mean the same thing
in both languages (the site's progress-tracking localStorage keys are shared across languages on
the same origin for this reason).

From that dataset, three separate presentations are built and must each be kept in sync by hand:

1. **Root static site** (`index.html`) — the original Persian design. Hand-written, fetches
   `data/roadmap.json` at runtime.
2. **`en/index.html`** — the English static site. **Not hand-written.** It's generated by
   `scripts/build_en_page.py`, which does a scripted find/replace pass over `index.html` (UI
   strings, `dir`, asset paths, digit formatting). If you change `index.html`'s structure or any
   string the script matches on, re-run the script — it prints a warning listing any expected
   replacement it couldn't find.
3. **`web/` (Next.js, App Router, Tailwind v4)** — the newer, animated "v2" redesign, a from-scratch
   component rewrite (boot-loader animation, roadmap.sh-style phase overview), not a port of
   `index.html`. It has its own copy of the content at `web/src/data/*.json` — **copy the regenerated
   `data/*.json` files there by hand** after running the generators; nothing does this automatically.
   `web/` is a static export (`output: "export"` in `next.config.ts`); there is no server-rendering
   or API route in this app.
4. **`app/` (Flask + SQLite)** — a separate, real multi-user prototype (registration, `user`/`admin`
   roles, admin panel, server-side activity heatmap). This one reads `../data/roadmap.json` and
   `../data/roadmap.en.json` directly at import time, so it's always in sync automatically — no
   copy step needed here.

`assets/` holds the canonical logo/favicon; `app/static/` and `web/public/` each have their own
copies that need to be refreshed by hand if the logo changes.

Both `index.html` and `en/index.html` render each day with a stable `id="day-N"` anchor and a
`#day-N` deep link (with hash-based scroll-on-load/hashchange handling, see `goToHashDay()` in
`index.html`). Any change to the day-card markup must be mirrored the same way in both files (via
`scripts/build_en_page.py` for the EN copy) — this anchor is a load-bearing integration point for
`telegram/` (below), not just a UI nicety.

## `telegram/` — Telegram learning-companion sync (separate component, own README)

A read-only pipeline (scan the 3 configured source channels → match against roadmap days →
preview) that will eventually publish to two personal Persian/English Telegram channels
structured after the roadmap. **Publishing is not implemented; nothing in this codebase sends,
forwards, or edits anything on Telegram.** No real Telegram credentials exist anywhere in this
repo — `telegram/config.py` fails loudly (`ConfigError`) if live scanning is attempted without
them, and the CLI defaults to a `--fixture` (synthetic, clearly-labeled sample data) path instead.
Full architecture, current weaknesses, and the pre-full-scan checklist are in `telegram/README.md`
— read that before extending this component, not just this summary.

## Deployment topology

- **GitHub Pages** (auto-deploys on push to `main`) serves the root site, `/en/`, and `/v2/`.
  `/v2/` is a **build artifact**, not source — it's `web/out/` from a
  `NEXT_PUBLIC_BASE_PATH=/bug-bounty-roadmap/v2` build, copied in by hand. After copying, rebuild
  `web/` *without* that env var so the local systemd service (which expects root-relative paths)
  isn't left serving subpath-prefixed assets. Don't hand-edit anything under `v2/`.
  **`.nojekyll` at the repo root is required** — GitHub Pages' default Jekyll processor silently
  drops any `_`-prefixed path, which would otherwise eat the Next.js `_next/` asset folder entirely
  (this broke the first `/v2/` deploy: page loaded with zero CSS).
- **This machine** also runs two systemd **user** services (`~/.config/systemd/user/`,
  lingering enabled) that are outside the repo: `bug-bounty-roadmap.service` (serves `web/out` on
  :3000) and `bug-bounty-roadmap-app.service` (`app/server.py` on :9876). Restart with
  `systemctl --user restart <name>` after rebuilding.
- Cloudflare Pages/Workers deployment is wired up (`web/wrangler.jsonc`) but not currently live —
  see `web/DEPLOYMENT.md` for the exact blocker and how to unblock it.

## Content conventions

- Every resource link is expected to be free (this is a hard project requirement) and to actually
  resolve — links get spot-checked with `curl` before being added; if a resource turns out to be
  paid, say so explicitly in the day's task text rather than removing the mention outright.
- `data/changelog.json` is both the human-readable changelog (mirrored into `README.md`'s table)
  and the data the sites' notification bell reads at runtime — new entries need `id` incremented
  and both `_fa`/`_en` fields filled in.
